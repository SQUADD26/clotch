# Architecture — Clotch

## What the project is
A macOS notch app that shows only the goals of Roberto's master Claude sessions and whether each goal is getting closer (issue #1). It started as a fork of Clotch (wxtsky, MIT, Swift): the notch shell, window and open/close motion come from it; the content is replaced by the goal list. App name `Clotch`, bundle id `com.squadd.clotch`, repo `SQUADD26/clotch` (issue #30; until then `Clotch`, `com.squadd.goalnotch`, repo `clotch`). Since issue #69 no Clotch or clotch name is left in the package, targets, sources, scripts or texts; only `LICENSE` (the MIT notice) and the README credit name Clotch. A normal app: Dock icon while it runs, app menu with Impostazioni… (Cmd+,) and Esci (Cmd+Q), a Dock click opens the settings. At the first launch `Sources/Clotch/main.swift` copies the old `com.squadd.goalnotch` UserDefaults once, without overwriting; then it renames the keys `clotch.rejectedProposals` / `clotch.seenMergedPRs` to `clotch.*` and deletes the old cache folder `Application Support/Clotch` (`ClotchCore/LegacyDefaults.swift`).

## Backend and where it runs
No backend. The app runs on Roberto's Mac only and reads local files, read-only. Its only write is its own cache, `~/Library/Application Support/Clotch/sessions-v<N>.json` (stat and parsed fields of each session file, so a restart re-parses only changed files; safe to delete). One exception, on Roberto's click (issue #20): «Accetta» / «Rifiuta» on a proposed goal run `python3 ~/.claude/hooks/obiettivo-guard.py conferma|rifiuta --sessione <cli>` (claude-config#1807) without `CLAUDE_CODE_SESSION_ID`, which write `~/.claude/obiettivi/` (`ClotchCore/GoalDecision.swift`); a rejected proposal is also hidden at once through UserDefaults `clotch.rejectedProposals`. Second exception, the voice (issues #38, #50; `ClotchCore/VoiceFiles.swift`, `VoiceHooks.swift`, `VoiceTurn.swift`, `VoicePrompt.swift`; app `VoiceSettingsPage.swift`, `VoiceSpeaker.swift`). The «Voce» page writes, on Roberto's save: the ElevenLabs key `~/.config/elevenlabs/api-key`, `~/.config/voce/config.json` (only `voice_id`, `model_id`, `speed`, `tetto_chiamate`, `tetto_caratteri`, and «Parla per» `parla_per` = `tutte` | `principali` (default: sessions with no parent session in the Claude app's session file) | `una` with `sessione` = a local id; other fields kept; a broken file is never overwritten), `~/.config/voce/spento` (voice off) and Haiku's instructions `~/.config/voce/prompt.md` (empty or stock text = file removed; the stock text is built into Clotch, `VoicePrompt.stock`, canonical copy claude-config#1837). Every file 600, folders 700, the key never read back. With the voice on and a key set, Clotch adds ONE Stop hook (command `~/.clotch/voce-stop.sh`, the script it writes) to `hooks` of every Claude Code folder's `settings.json` (`~/.claude` and each `~/.claude-*` with `settings.json` or `projects/`; minimal-diff edit like the inherited hook installer, a non-JSON file is never touched), once; voice off or no key removes the entries and the script. It writes the empty file `~/.config/voce/clotch` and touches it every hour while it runs (removed at quit and when the voice goes off): the hook queues the Stop payload in `~/.config/voce/coda/` only while that file is younger than 90 min, and Clean View's mod stays silent while it is younger than 24 h (contract in PR #55). For each queued turn (older than 2 min or third in line: dropped): checks `spento`, the key, «Parla per», `muto-<session_id>`, the daily caps in `giorno.json`; runs `claude -p --safe-mode --model claude-haiku-5-5` with the instructions (report on stdin, env `CLOTCH_VOCE_INTERNA=1` so the hook skips it); ElevenLabs TTS; writes `stato.json` (the light's contract below) and `ultima.json`; plays with AVAudioPlayer (speed above 1.2 by the player's rate). Otherwise it writes nothing into `~/.claude`, `~/.codex` or other agent configs (the inherited hook installer, hook socket server, agent watchers and companion bridges are not started at launch).

## Data the app reads (all on the Mac, read-only)
| What | Path | Written by |
|---|---|---|
| Goals register, one file per master session | `~/.claude/obiettivi/<cli>.json` (`cli`, `obiettivo`, `stato` aperto/proposto/raggiunto/bloccato (shown), passato/rifiutato/nessuno (hidden), `ultima_attivita` = the hook's sign of life, which «fermo da» counts from, `prova`, `t`, `titolo`, `prove` = `[{testo, fatta, t}]` when present, `proposta.testo` = a proposal beside the open goal) | claude-config `global/hooks/obiettivo_registro.py` |
| Desktop app sessions | `~/Library/Application Support/[Cc]laude*/claude-code-sessions/**/local_*.json` (only these top-level keys are parsed, the rest is skipped: `sessionId`, `cliSessionId`, `spawnedFrom`, `priorRemoteCliSessionIds`, `scheduledTaskId`, `title`, `isRunning`, `isArchived`, `lastActivityAt`, `prs`) | Claude desktop app |
| Click on a goal title or a taken request (#19) | `claude://claude.ai/epitaxy/local_<id>`, opened with the Claude app copy whose launcher `Contents/MacOS/launcher` (`~/Applications` or `/Applications`, `Claude <email>.app`) sets `--user-data-dir` to the session file's profile folder (`Application Support/Claude-x`); no copy matches: the default app. A request names its taker by cli id (`presa_da`), mapped to the session file by `cliSessionId` | Claude desktop app copies, claude-config `claude_accounts_app.py` |
| Live subagents per session | `~/.claude/handoff/live/<cli>.json` (`agenti`, `aggiornato`) | claude-config `global/hooks/live_state.py` |
| Accounts in use on this Mac | running apps (`NSWorkspace.runningApplications`): bundle `Claude <email>.app` (full-width ＠ in the name), matched to the dashboard row by exact email; updated on app launch/quit notifications only | each account's Claude desktop app |
| Roberto's requests | `~/.claude/richieste/<id>.json` (`id`, `t`, `testo`, `stato` nuova/presa/fatta, `t_presa`, `tipo` compito/domanda/nota, …; only tasks are shown, no `tipo` = a task, #61); the folder arrives with a claude-config promotion, until then the plate says so | claude-config (Overseer) |
| Overseer voice state (issue #10) | `~/.config/voce/stato.json` (`v`, `parla`, `t_inizio`/`t_fine` epoch ms, `passo_ms`, `livello` = volume 0…1 per step, computed from the mp3 before it plays); contract in `ClotchCore/NotchVoice.swift`; FSEvents file events on `~/.config`, no polling | Clotch `VoiceSpeaker.swift` while `~/.config/voce/clotch` is fresh, else claude-config Clean View `voce-io.ts` (player) |

Real time: one FSEvents stream with file-level events, batched by FSEvents to one callback a second. Each reload touches only the paths the events named (`GoalLoader`): the 1600+ session files are listed at launch and parsed only if changed since the on-disk index, then a rewrite costs one stat and one parse; only sessions in a shown goal's family reach the board, and an unchanged value publishes nothing. A full rescan happens only at launch, when FSEvents drops events, or when a new Claude app folder appears. A 30 s tick moves only the «since …» time; time-based state (yellow after 30 min still) is re-evaluated by a one-shot timer at the next instant it can change.

## Code layout
- `Sources/ClotchCore/GoalBoard.swift`: pure logic, goal → progress, traffic light, reason, session pulses. Tests in `Tests/ClotchCoreTests/GoalBoardTests.swift`.
- `Sources/ClotchCore/PullRequests.swift` + `Sources/Clotch/PullRequestFeed.swift` (issue #6, data only, no view yet): which PRs belong to a goal (`prs` of the family's session files, archived children included, plus PR links and `#N` in its proofs), the batched GraphQL query and the state mapping (merged, closed, green, pending, red, conflict). `PullRequestTracker.swift` holds the display rule: only OPEN PRs stay; a PR seen merged for the first time is one event, then dropped (merged PRs already shown are remembered in UserDefaults `clotch.seenMergedPRs`; the first pass after launch is a silent baseline); closed-unmerged vanish. Tests in `PullRequestsTests.swift`.
- `Sources/ClotchCore/GoalSources.swift`: parses the files above. `GoalLoader.swift` + `GoalFileCache.swift`: the incremental reader the watcher keeps (cache by mtime and size, work per changed path, only goal-family sessions reach the board, the on-disk index above).
- `Sources/Clotch/GoalStore.swift`: FSEvents watcher, publishes rows to the UI.
- The notch view (issue #3), one Liquid Glass design inside the black notch kept from Clotch (`NotchPanelView.swift`, `PanelWindowController.swift`): `NotchSections.swift` (scale and plate) + `NotchAccountsPlate.swift`, `NotchGoalPlate.swift`, `NotchRequestsPlate.swift` (open: account usage, the goal chased now with the other goals, Roberto's requests), `GoalsNotchWings.swift` (closed: state, bar and proofs of the goal chased now), `NotchNotificationView.swift` + `NotchNotifier.swift` (notifications under the closed notch: goal changes from `ClotchCore/NotchEvents.swift`, requests from `GoalStore.takenToAnimate`), `NotchGlass.swift` (real `glassEffect` on macOS 26+, a stand-in before and in snapshots), `NotchTokens.swift` (colour, spacing and type tokens: the one file the approved Figma target changes), `ClotchCore/NotchIsland.swift` (the island is a column centred in the fixed window and hung from its top, so it opens straight down, #33), `GoalsNotchView.swift` (shared pieces).
- The voice light (issue #10): `ClotchCore/NotchVoice.swift` (contract, parser, level off the clock), `VoiceStore.swift` (file watcher, one-shot expiry), `VoiceEdgeLight.swift` (edge glow on the notch outline; a clock runs only while it is in the tree; Reduce Motion = steady). The notch view plugs it in.
- Everything else under `Sources/` is Clotch code kept for the shell; most of it is not reached at launch.
- Clotch's companions (Android watch, iOS/watchOS, Windows, ESP32 hardware, App Store files), its changelog, appcast, release and DMG workflows were removed in #69: never built or used by Clotch.

## Build
- Swift package (`Package.swift`, macOS 14+, Sparkle and Yams via SwiftPM).
- `./build.sh` on a Mac with Xcode: `swift build -c release --arch arm64`, then assembles `.build/release/Clotch.app` (SwiftPM package, product and executable `Clotch`, helper `clotch-bridge`, resource bundle `Clotch_Clotch.bundle`, entitlements `Clotch.entitlements`; `--notarize` uses the notarytool keychain profile `clotch`). App icon, logo 38 (#58) everywhere: `AppIcon.icon` and `Sources/Clotch/Resources/AppIcon.icns` (Dock, Finder, About through `NSWorkspace.icon`), `AppLogoView` (About, notch) and the menu bar template drawn from the same grid (`StatusItemController.menuBarIcon`); `logo.svg` is the README copy, ad-hoc signed unless `SIGN_ID` or a Developer ID is found.
- `Clotch.app/Contents/MacOS/Clotch --snapshot <dir> [--gallery]` renders the real notch from the live data to PNG and quits: closed, open, and with `--gallery` three frames of each notification today's data can produce (`GoalSnapshot.swift`). ImageRenderer cannot sample a backdrop, so the glass shows as its stand-in there; the real glass shows only in the running app.
- Linux sandboxes cannot build the app. They can run the goal logic tests: `bash scripts/test-goals-linux.sh`.

## Domains, ports, machines
None. No network service, no ports. Runs only on Roberto's Mac; developed in the `squaddv2` sandbox.

## Branches and path to production
Work branches → PR into `dev` → promotion PR `dev` → `main`. "Production" is the app built from `main` and run on the Mac. No migrations, functions or deploys. Auto-update (Sparkle) is off: no `SUFeedURL`, no Clotch signing key in `Info.plist`, no update button in About, so Clotch can never download the original Clotch app.

## Secrets
The app holds none in its code. The «Voce» page writes the user's ElevenLabs key to `~/.config/elevenlabs/api-key` (600); the speaker reads it only to put it in the `xi-api-key` header of the TTS request, never in a command line, a URL or a log.

## External services
Voice (only with the voice on and a key): ElevenLabs `POST https://api.elevenlabs.io/v1/text-to-speech/<voice_id>` per spoken turn; the local `claude` CLI for the Haiku rewrite (the user's own Claude login, `--max-budget-usd 0.02` a call). At runtime one read-only HTTPS GET, no token: account usage from `https://claude.squaddbackend.com/dashboard/data` (the dashboard Roberto's Macchine app reads; same merge and order rules, `ClotchCore/AccountQuota.swift`, fetched by `AccountQuotaFeed.swift` at launch, every 60 s and when the notch opens; a failed fetch keeps the last good list and shows its age). Pull request state: one `gh api graphql` call (the `gh` already signed in on the Mac; no token asked or stored) for all PRs of the goals, run only when the notch opens or when the set of PRs changed, never on a timer; a failed call keeps the last good state and its time. CI: GitHub Actions (`architettura.yml`, an inline copy of the claude-config check on `ubuntu-latest`: this repo is public and cannot call a private reusable workflow or use the self-hosted runners; it is the only workflow).
