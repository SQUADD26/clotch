# Architecture — Clotch

## What the project is
A macOS notch app that shows only the goals of Roberto's master Claude sessions and whether each goal is getting closer (issue #1). It started as a fork of CodeIsland (wxtsky, MIT, Swift): the notch shell, window and open/close motion come from it; the content is replaced by the goal list. App name `Clotch`, bundle id `com.squadd.clotch`, repo `SQUADD26/clotch` (issue #30; until then `Goal Notch`, `com.squadd.goalnotch`, repo `goal-notch`). Since issue #69 no CodeIsland or goal-notch name is left in the package, targets, sources, scripts or texts; only `LICENSE` (the MIT notice) and the README credit name CodeIsland. A normal app: Dock icon while it runs, app menu with Impostazioni… (Cmd+,) and Esci (Cmd+Q), a Dock click opens the settings. At the first launch `Sources/Clotch/main.swift` copies the old `com.squadd.goalnotch` UserDefaults once, without overwriting; then it renames the keys `goalnotch.rejectedProposals` / `goalnotch.seenMergedPRs` to `clotch.*` and deletes the old cache folder `Application Support/Goal Notch` (`ClotchCore/LegacyDefaults.swift`).

## Backend and where it runs
No backend. The app runs on Roberto's Mac only and reads local files, read-only. Its only write is its own cache, `~/Library/Application Support/Clotch/sessions-v<N>.json` (stat and parsed fields of each session file, so a restart re-parses only changed files; safe to delete). One exception, on Roberto's click (issue #20): «Accetta» / «Rifiuta» on a proposed goal run `python3 ~/.claude/hooks/obiettivo-guard.py conferma|rifiuta --sessione <cli>` (claude-config#1807) without `CLAUDE_CODE_SESSION_ID`, which write `~/.claude/obiettivi/` (`ClotchCore/GoalDecision.swift`); a rejected proposal leaves the notch only when the register drops it (no copy kept in the app, #171; a refusal the register did not take shows «Non rifiutato. Riprova.»). Second exception, the voice (issues #38, #50; `ClotchCore/VoiceFiles.swift`, `VoiceHooks.swift`, `VoiceTurn.swift`, `VoiceClean.swift`; app `VoiceSettingsPage.swift`, `VoiceSpeaker.swift`). The «Voce» page writes, on Roberto's save: the ElevenLabs key `~/.config/elevenlabs/api-key`, `~/.config/voce/config.json` (only `voice_id`, `model_id`, `speed`, `tetto_chiamate`, `tetto_caratteri`, and «Parla per» `parla_per` = `tutte` | `principali` (default: sessions with no parent session in the Claude app's session file) | `una` with `sessione` = a local id; other fields kept; a broken file is never overwritten), `~/.config/voce/spento` (voice off). Haiku's instructions and the pronunciation list are claude-config's own files, read and never copied or written (#84, claude-config#1837): the prompt `~/.claude/mods/clean-view/hooks/voce-parlatore.md` (installed with the mod by `global/bin/installa`; missing or empty = the voice is silent), the base list `~/.claude/mods/clean-view/hooks/voce-pronuncia.json` with Roberto's `~/.config/voce/pronuncia.json` on top (`{"parola": "come si dice"}`, whole words, an all-capitals key matches capitals only, applied to the text sent to ElevenLabs). Every file 600, folders 700, the key never read back. With the voice on and a key set, Clotch adds ONE Stop hook (command `~/.clotch/voce-stop.sh`, the script it writes) to `hooks` of every Claude Code folder's `settings.json` (`~/.claude` and each `~/.claude-*` with `settings.json` or `projects/`; minimal-diff edit like the inherited hook installer, a non-JSON file is never touched), once; voice off or no key removes the entries and the script. It writes the empty file `~/.config/voce/clotch` and touches it every hour while it runs (removed at quit and when the voice goes off): the hook queues the Stop payload in `~/.config/voce/coda/` only while that file is younger than 90 min, and Clean View's mod stays silent while it is younger than 24 h (contract in PR #55). The voice speaks only for news (#57, alerts engine `ClotchCore/VoiceEvents.swift`, `VoiceAlerts.swift`; app `VoiceAlertCenter.swift`): `richiesta_fatta`, `obiettivo_raggiunto`, `obiettivo_bloccato`, `fine_turno`, `domanda`, `rischio`, `avviso_custom`. If `~/.config/voce/eventi.jsonl` exists (claude-config#1854, contract `global/skills/overseer/eventi.md`, v 1, one JSON per line: `id`, `t`, `tipo`, `livello`, `sessione` {`cli`, `local_id`, `titolo`, `ruolo`}, `soggetto`, `testo`, `prova`, `giudizio`), only its events after launch count, found by the `t` and `id` of the last one seen, never by byte (read, never written). Otherwise Clotch derives them: a queued turn (older than 2 min: dropped) gives `domanda` from the questions of its last `giro_finito`/`needs_you` call, else an answer ending with «?»; the goals register going `raggiunto`/`bloccato`; a request going `fatta`; an account window crossing 80 % or 90 %; and the «Avvisami quando…» rules of `~/.config/voce/avvisi.json` (`{"v": 1, "regole": [{id "A-xxxx", creata, condizione, quando: {tipo: pr-fusa|sessione-ferma|file|ora|testo, valore, repo} | null, stato: attiva|scattata}]}`, written by the «Voce» page and by claude-config's `avvisami`; Clotch edits the file's own objects, so unknown fields stay, never overwrites a broken file, sets only `stato` = `scattata`, once, and checks them only without `eventi.jsonl`; a rule with no `quando` is the Overseer's). Before the engine, `richiesta_fatta`, `obiettivo_raggiunto`, `obiettivo_bloccato` and `fine_turno` without `giudizio` go to the Jev judge (`ClotchCore/VoiceJudge.swift`; the question is the config's file `~/.claude/hooks/voce_giudice_domanda.txt`, read and never copied, missing = the judge is not asked, #84; same three blocks as claude-config `voce_giudice.py`: Roberto's linked requests verbatim, the session's goal, the signal); no = silent, not reached (no question file, no key, error, over 5 s) = the fixed rules; every verdict appends a line to `~/.config/voce/giudice-log.jsonl` (600, never the key). The engine applies «Parla per» (`ruolo` master|overseer for «principali» and `local_id` for «una» when the event has them, else the session file; events with no session pass), one per subject in 10 min unless the new one is `alto` and the old one not, one of `richiesta_fatta`/`obiettivo_raggiunto` per session in 10 min, a queue of 3 (risks and questions first, `livello` alto ahead), no event older than 5 min. For each event said: checks `spento`, the key, `muto-<session_id>`, the daily caps in `giorno.json`; runs `claude -p --safe-mode --model claude-haiku-5-5` with the instructions (report on stdin, env `CLAUDE_CONFIG_DIR` = the account folder `ClaudeRun` picked (#159: the Dock-launched app has no CLAUDE_CONFIG_DIR and `~/.claude` may have no login; candidates = main folder, Settings extras, every `~/.claude-*`, ordered by the Macchine margin, first one `claude auth status --json` calls logged in, kept 10 min; stderr and exit status go to the log, category `ClaudeRun`, and a spoken question that fails shows why in the bar), `CLOTCH_VOCE_INTERNA=1` so the hook skips it; 22 s a try, two tries, then silence, #84: never the report itself, never a fixed sentence such as «guarda lo schermo», never «io dico/consiglio sì»); ElevenLabs TTS; writes `stato.json` (the light's contract below) and `ultima.json`; plays with AVAudioPlayer (speed above 1.2 by the player's rate). With the switch «Abbassa l'audio mentre parlo» on (`abbassa_audio`, default off, and `abbassa_livello` in percent, default 20, 0 to 80, both in `config.json`; #83) the other apps' audio goes down over 0.5 s before the first word, stays down 0.5 s after the last, and rises over 0.5 s (`ClotchCore/VoiceDuck.swift`: timing and the guarantee that it is always given back; app `AudioDucker.swift`). The tool is a Core Audio process tap (macOS 14.2+, `CATapDescription` of every other audio process, `mutedWhenTapped`) played back by a private aggregate device with a gain ramp. Clotch's own voice is not in the tap and the system volume is never touched, so the level returns exactly and a volume change by Roberto during the speech applies to both. The tap ends with the speech, at quit, or with the process. `Info.plist` has `NSAudioCaptureUsageDescription`: the first use asks macOS for System Audio Recording. Otherwise it writes nothing into `~/.claude`, `~/.codex` or other agent configs (the inherited hook installer, hook socket server, agent watchers and companion bridges are not started at launch). Otherwise it writes nothing into `~/.claude`, `~/.codex` or other agent configs (the inherited hook installer, hook socket server, agent watchers and companion bridges are not started at launch). Third exception, the voice in (issue #110; Core `VoiceInput.swift`, `VoiceRoute.swift`; app `VoiceInputController.swift`, `VoiceCapture.swift`, `ScribeSession.swift`, `LocalTranscriber.swift`, `VoiceAsk.swift`, `OverseerDelivery.swift`, `VoiceInputPill.swift`, `DictationPage.swift`): the global shortcut `ShortcutAction.voiceInput` (default ⌥Spazio, UserDefaults; mode `tieni` = hold to speak and release to finish, a tap under 0.35 s leaves it open until the next press; mode `premi` = press to speak, press again to finish; 60 s cap) records the microphone as 16 kHz mono (`NSMicrophoneUsageDescription`, entitlement `device.audio-input`) and shows the live text on a pill under the notch. Engine from `~/.config/voce/config.json` keys `ingresso_motore` (`scribe` default | `locale`), `ingresso_lingua` (`it` default | `en` | `auto`), `ingresso_a_voce` (default true), `ingresso_modo` (`tieni` default | `premi`), `ingresso_acceso` (default true; false = the shortcut does nothing), `ingresso_microfono` (unique id of the input device, "" = the system's), written by the «Dettatura» settings tab (microphone permission status with a button to Privacy, shortcut, mode, engine, language, microphone, spoken answers; the ElevenLabs key stays in «Voce»). `scribe` = ElevenLabs Scribe v2 Realtime WebSocket; `locale` = Parakeet TDT v3 through the FluidAudio package (Core ML model, ~480 MB downloaded once from Hugging Face, then no network). Where the text goes (`VoiceRoute.classify`, the registry rules of `richieste.py`): a question runs `claude -p --safe-mode --model claude-haiku-5-5` with read-only tools (Read, Glob, Grep, `gh` view/list) from `~/.claude` and the answer is said with the voice of the «Voce» page; an order is a file `~/.config/voce/ingresso/<ms>-<id>.json` (`{"v":1,"id","t","testo","da":"clotch-voce"}`, 600) that Clean View's mod in the Overseer's chat reads, submits as a prompt and deletes (deleted = received); the mod touches `~/.config/voce/ingresso/.ascolta` every 30 s while it listens. No fresh `.ascolta`, or the file still there after 20 s: Clotch deletes it, copies the text to the clipboard, opens the Overseer's chat (`local_id` in `~/.claude/overseer/attuale.json`) and the pill says to paste. An order waits 2 s on the pill («Annulla · 2», or Esc) before it leaves; Esc is a Carbon hotkey registered only while a dictation is open. Errors (microphone refused, key refused, credits over, no network, silence) are plain sentences with a button each (`VoiceInput.Failure`, no codes); the microphone error restarts by itself when macOS grants the permission. While he speaks the island's outline has a white light (red and flashing on an error), `VoiceInputLight.swift`.

Real time: one FSEvents stream with file-level events, batched by FSEvents to one callback a second. Each reload touches only the paths the events named (`GoalLoader`): the 1600+ session files are listed at launch and parsed only if changed since the on-disk index, then a rewrite costs one stat and one parse; only sessions in a shown goal's family reach the board, and an unchanged value publishes nothing. A full rescan happens only at launch, when FSEvents drops events, or when a new Claude app folder appears. A 30 s tick moves only the «since …» time; time-based state (yellow after 30 min still) is re-evaluated by a one-shot timer at the next instant it can change.

## Domains, ports, machines
None. No network service, no ports. Runs only on Roberto's Mac; developed in the `squaddv2` sandbox.

## Branches and path to production
Work branches → PR into `dev` → promotion PR `dev` → `main`. "Production" is the app built from `main` and run on the Mac. No migrations, functions or deploys. Auto-update (Sparkle) is off: no `SUFeedURL`, no CodeIsland signing key in `Info.plist`, no update button in About, so Clotch can never download the original CodeIsland app.

## Secrets
The app holds none in its code. The «Voce» page writes the user's ElevenLabs key to `~/.config/elevenlabs/api-key` (600); the speaker reads it only to put it in the `xi-api-key` header of the TTS request, never in a command line, a URL or a log. The same page writes the Jev key to `~/.config/jev/api-key` (600, the file claude-config's command judge reads); the judge puts it only in the `Authorization: Bearer` header. The voice in puts the same ElevenLabs key only in the `xi-api-key` header of the Scribe WebSocket; the microphone audio goes nowhere else, and not at all with the local engine.

## External services
Voice (only with the voice on and a key): ElevenLabs `POST https://api.elevenlabs.io/v1/text-to-speech/<voice_id>` per spoken turn; with a Jev key, Jev (typesafe.ai) `POST https://api.typesafe.ai/v1/systemone` (model `jev-1.13.0`, timeout 5 s) per event that goes to the judge; the local `claude` CLI for the Haiku rewrite (the user's own Claude login, `--max-budget-usd 0.02` a call). At runtime one read-only HTTPS GET, no token: account usage from `https://claude.squaddbackend.com/dashboard/data` (the dashboard Roberto's Macchine app reads; same merge and order rules, `ClotchCore/AccountQuota.swift`, fetched by `AccountQuotaFeed.swift` at launch, every 60 s and when the notch opens; a failed fetch keeps the last good list and shows its age). Pull request state: one `gh api graphql` call (the `gh` already signed in on the Mac; no token asked or stored) for all PRs of the goals, run only when the notch opens or when the set of PRs changed, never on a timer; a failed call keeps the last good state and its time. CI: GitHub Actions (`architettura.yml`, an inline copy of the claude-config check on `ubuntu-latest`: this repo is public and cannot call a private reusable workflow or use the self-hosted runners; it is the only workflow). Voice in: with the Scribe engine, ElevenLabs `wss://api.elevenlabs.io/v1/speech-to-text/realtime?model_id=scribe_v2_realtime` while Roberto speaks; with the local engine, one download of the Parakeet v3 Core ML model from Hugging Face (FluidAudio) at first use.

## Contract with the engine (claude-config#1921)
`Tests/Fixtures/motore/*.json` are files the engine's own code wrote (claude-config `global/hooks/test_contratto_clotch.py --aggiorna`); `Tests/ClotchCoreTests/EngineContractTests.swift` reads them with the real parsers. The folder must stay identical to claude-config `global/hooks/contratto-clotch/`: change both in the same piece of work. Files Clotch writes into the engine's folders keep every field it does not own: `giorno.json` (`VoiceTurn.Day.merged`, Clean View's `recenti`/`avvisato`/`ultimo` stay) and `avvisi.json` (under the engine's flock `avvisi.lock`, `VoiceFiles.modify`; a rule fired by Clotch gets `scattata` so the engine's 7-day prune counts from it).
